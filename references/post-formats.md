# 帖子格式

## 默认约定

默认交付一篇讲完整的中文蓝 V X 单帖。除非用户明确要求 Thread，否则正文不要拆成 Thread；长度由信息价值和可读性决定，不套用固定字数或固定条数。

链接位置取决于读者效用、阅读路径和账号实测数据。原始来源或操作入口对理解正文有直接帮助时，链接可以保留在主帖；不要把“外链一律放在回复区”写成平台规律。

所有格式都应忠于 Research Summary 的事实、推断、观点和未知边界。正文之外可附来源与审核说明，但不要把研究过程全部塞进正文。

## 完整单帖

按“开头判断或读者问题 -> 证据或过程 -> 有用解释 -> 适用边界 -> 自然收尾”推进。

- 开头说明为什么这件事值得读，而不是只追求悬念。
- 中段提供足以支撑判断的事实、机制、步骤或案例。
- 边界说明哪些情况不适用、哪些仍未知。
- 收尾完成观点即可，不强制 CTA、问题或 Hashtag。

## 教程

按“结果 -> 前置条件 -> 精确路径 -> 失败点 -> 限制 -> 来源”组织。

- 先说明读者完成后能得到什么。
- 给出版本、权限、依赖和环境等必要前置条件。
- 步骤使用可执行的准确路径，并说明关键可观察结果。
- 写出常见失败点、排查方向和未覆盖情形。
- 标明实测、仅核对文档或待验证状态，不把项目存在写成稳定好用。

## 引用观点

按“来源主张 -> 缺失上下文 -> 自己的判断 -> 为什么重要”组织。

- 准确呈现原帖主张和必要上下文，不用稻草人替代原意。
- 明确区分来源观点与作者判断。
- 补充、质疑或重新解释至少一处有信息价值的内容。
- 避免只复述原帖或用空泛赞同开头。

## 经济/加密分析

按“事件 -> 传导机制 -> 受影响群体 -> 反例或反向情景 -> 观察指标”组织。

- 把价格、政策、日期和主体身份作为时效事实核验。
- 解释事件如何影响流动性、成本、预期、供需或风险偏好，不只描述涨跌。
- 写出主要受益者、承压者和影响条件。
- 给出至少一个可能推翻当前判断的反例或反向情景。
- 用可继续观察的指标收尾，不给无依据的价格保证。

## 关心/好奇问题

提出一个真诚问题，并提供足够上下文，让回答值得投入时间。

- 说明为什么会关心这个问题，以及已经知道什么。
- 缩小问题范围，避免用宽泛提问代替内容。
- 不预设答案，不为了互动强行制造对立。

## 审阅

先诊断，再决定是否改写。

- 先指出问题属于事实、角度、结构、语气、证据还是视觉，并说明理由。
- 只有用户要求改写，或任务已明确包含改写时，才提供修订版本。
- 修订时保留作者真实观点和有价值的原句，不统一套成爆款模板。
- 不输出伪精确的流量分数或平台算法预测。
