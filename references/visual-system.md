# 视觉系统

视觉是第二条信息线，不是装饰。先确认正文需要证明或解释什么，再选择真实素材、图表或概念图。每张图只承担一个主要任务，生成内容不得冒充证据。

## 视觉来源优先级

按内容类型使用以下决策顺序：

1. `Tutorial -> real UI screenshots and annotated steps.` 教程优先真实界面截图、关键步骤标注和可观察结果。
2. `Finance/economics -> sourced charts, timelines, and mechanism diagrams.` 金融与经济内容优先有来源的数据图、时间轴和传导机制图。
3. `GitHub project -> real repository pages and locally verified output.` GitHub 项目优先真实仓库页面与本地验证输出，不能用生成界面代替。
4. `Abstract opinion -> original editorial photography or poster art.` 抽象观点可使用原创编辑摄影感画面或克制的海报艺术。
5. `No suitable real visual -> controlled diagram or clearly labeled generated concept image.` 没有合适真实素材时，使用可控排版的图解，或明确标注为生成概念图。

真实截图和数据图必须保留足以判断来源、时间和上下文的信息。需要遮挡隐私或密钥时可裁切、打码，但不能改变证据含义。生成式图片不得表现成新闻现场、产品真实截图、真实人物活动或数据证据。

## 1–4 图叙事

- `Image 1: subject and core judgment.` 主题与核心判断，让读者快速知道内容在讲什么。
- `Image 2: evidence or real operation.` 证据、真实操作或关键来源。
- `Image 3: mechanism, steps, or before/after.` 机制、步骤或前后对比。
- `Image 4: limits, conclusion, or action checklist.` 限制、结论或行动清单。

不要求凑满四张。新增图片没有提供新证据、新步骤或新解释时，优先减少图片数量。图片顺序应能独立形成从主题到证据、机制和边界的叙事，但不能重复正文大段文字。

## 视觉 QA

交付前必须逐张打开并检查每一个最终 PNG，不以源文件预览或生成成功代替最终检查：

- 移动端缩放后，标题、数据、来源注释和关键步骤仍清晰可读。
- 中文文字准确，无错字、乱码、漏字、字体替换或不自然断行。
- 数据、图表和事实性文字附来源说明、时间范围和必要单位。
- 不使用伪造 UI；示意界面必须明确标为示意，不能暗示真实产品输出。
- 不使用生成式新闻现场图，不把生成画面表示为真实事件或现场证据。
- 海报不堆叠密集段落；长解释留在正文，图片只保留必要信息。
- 检查裁切、边距、对齐、对比度、品牌或主体误认，以及意外暴露的隐私信息。
- 确认每张图提供不同信息，并与正文的事实边界一致。

复杂中文信息图优先使用可控排版生成，事实性文字完成后再次人工核对。若最终 PNG 任一项不合格，修正后重新打开检查。
